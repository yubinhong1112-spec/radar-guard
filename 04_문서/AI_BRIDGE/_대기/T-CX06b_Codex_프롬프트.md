# T-CX06b — event_log 기간 해석 결함 수정 (Codex 채팅에 그대로 붙여 넣기)

> 이 프롬프트가 유일한 지시다. Ollama·DB 미사용. 착수 보고 6항목 → 사용자 "진행" 후 시작.

## 배경 (Cowork 가 10/06 직접 실행해 확인한 결함)
`now = 2026-10-06 11:00` 에서 `parse_query` 결과:

| 질문 | 지금 결과 | 문제 |
|---|---|---|
| `9시부터 12시까지 입실 몇 건?` | 기간 `오늘`(0시~11시) | 질문한 구간이 아니라 하루 전체를 센다 |
| `오후 2시~5시 퇴실 건수` | `오늘` | 같음 |
| `오전 9시부터 오후 1시까지 입실 몇 건` | `오늘` | 같음 |
| `12시부터 1시까지 경보 몇 번` | `오늘` | 같음 |

원인: 기간 표현이 **있는데** `parse_period` 가 None 을 주면 `parse_query` 가 "기간 없음"으로 보고 기본값 `오늘` 로 바꾼다. 답변 문장에 "오늘"이 찍히긴 하지만, 사용자는 9~12시를 물었는데 하루 전체 수를 받는다 — 다른 질문에 답하는 것이다. 처음 지시의 "미래 구간이면 None" 규칙도 Cowork 지시가 과했다(11시에 "9시부터 12시까지"를 물으면 9~11시를 세는 것이 맞다).

## 고칠 것 (`01_현행코드/event_log.py`, `01_현행코드/eval/test_event_log.py` 만)
1. **기간 표현이 있는데 해석 실패 → 조용히 `오늘`로 바꾸지 않는다.** `parse_query` 가 `{"type": "unsupported_period", "raw": <원문 표현>}` 을 돌려주고, `answer` 는 "'○○' 구간은 해석하지 못했습니다. 예: 9시부터 12시까지, 오후 2시~5시, 최근 2시간" 처럼 지원 예시를 안내한다. 기간 표현이 아예 없을 때만 기본 `오늘`.
   - "기간 표현이 있다"의 판정: `\d+\s*시`, `오전|오후`, `최근`, `어제|오늘|그제|내일|지난|이번|아까|새벽|점심|저녁` 중 하나라도 있으면 있음.
2. **구간 끝이 미래면 현재 시각으로 자른다.** 시작이 미래면 그때만 거절(`unsupported_period`, 이유 "아직 오지 않은 시간"). 잘랐으면 답변에 "(현재 11:00까지)" 를 붙인다.
3. **오전·오후가 양쪽에 따로 붙은 범위 지원**: `오전 9시부터 오후 1시까지` → 9~13시.
4. **오전·오후 없이 끝 시각이 시작보다 작으면**(예: `12시부터 1시까지`, `11시~2시`) 끝에 12를 더해 같은 날로 해석(12~13시, 11~14시). 더해도 시작 이하이면 거절.
5. `12시` 단독은 정오(12:00), `오전 12시`는 거절(모호).

## 테스트 추가 (기존 81개 유지 + 최소 12개)
- 위 표 4문장 + 구간 끝 자르기 2개 + 시작 미래 거절 1개 + 오전/오후 교차 2개 + 끝<시작 보정 2개 + `오전 12시` 거절 1개.
- 기간 표현이 없는 질문(`입실 몇 번 했어?`)은 여전히 `오늘` 인지.
