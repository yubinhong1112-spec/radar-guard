## 1. 변형별 측정 (v1 DB, 같은 30문항, 같은 채점기=확장판)

한 번에 하나씩 바꿔서 무엇이 효과였는지 분리한다. 각 변형은 `build_chat_request`/호출 옵션에 플래그로 넣고 `chat_eval.py --variant <이름>` 으로 측정한다. 결과 파일: `results/<variant>_YYYYMMDD_HHMM.{md,jsonl}`.

| 변형 | 바꾸는 것 | 확인하려는 가설 |
|---|---|---|
| R (routing) | ① 키워드 없는 질문도 검색한다: 사용자 질문 그대로 `00_응급처치_공통`·`01_감전_대응`·`02_협착_예방`·`03_낙상_예방` 등 대응 카테고리 전체에서 벡터 검색 ② 키워드가 있는 질문은 검색어를 `사용자 질문 + SOP_QUERY[event]` 로 | keyword_free 0/6 의 원인이 라우팅이다 |
| R+P (prompt) | R + 사고 대응 질문(검색 결과가 있는 경우)에서 프롬프트 순서를 [공식 매뉴얼] → [질문] 중심으로 바꾸고, SYSTEM_CONTEXT 는 안전 규칙 2문장(LLM 은 판정·차단·해제·재투입을 하지 않는다 / 확정 즉시조치·책임자 지시가 우선)만 남긴다. "매뉴얼에 있는 조치만 번호로" 지시 | event_action 이 시스템 설명으로 새는 원인이 프롬프트다 |
| R+P+N | R+P + `num_predict` 100→220 | 잘림 해소가 추가 이득을 준다 |
| R+P+N+Q | 위 + 모델 `qwen2.5:3b-instruct-q4_K_M` | 2B→3B 의 한국어·지시 이행 차이 |

- 각 변형마다 잘림 비율, must 통과, 금지 위반, 거절, 출처 적중, p50/최대, **문항별 소요 시간**(이상치 즉시 확인)을 기록.
- **모델 교체는 측정만 하고 코드 기본값은 바꾸지 않는다.** OUT-007 규칙(결과를 크게 바꾸는 변경은 사용자 사전 승인). 채택 여부는 표를 보고 사용자가 정한다.
- 측정 중 Ollama 를 다른 프로세스가 쓰지 않는지 확인. 관제 UI 종료 상태 유지.
- 측정 전 PC 절전 해제 여부를 사용자에게 확인(LS-05 재발 방지).
- **측정 시작 직전, Codex 의 `safety_manual_v2` 적재(T-CX03, bge-m3 임베딩)가 끝났는지 사용자에게 확인받는다.** 동시에 돌면 CPU 경합으로 지연 수치가 오염된다. 0-A(커밋·push)와 재채점은 Ollama 를 안 쓰므로 먼저 해도 된다.
