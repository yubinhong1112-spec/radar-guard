## 배경 (10/06 결정)
- 경보 화면에서는 생성형 AI 를 뺐다. **RAG(검색+생성)는 챗봇이 담당**한다. 런타임 LLM 은 챗봇용 1개.
- 지금까지 챗봇의 결함(실측): 무작위성(temperature 0.2), 안전 규칙 문장 베끼기, 답 잘림, 사고 질문 근거 조각 오선택(용어 빈도 — EA-05 감전 질문에 화상 절), 보안 질문 사실 오류(OS-06 "레이더로 영상 분석"), 조작 질문 금지 발언(baseline temp0 EA-01 "복구를 진행"·OS-03 "해제를 진행" 고정 재현).

## 2. 변형 `J` = `I` + 아래 5가지 (console_ui.py, 기본값 무변경)
1. **temperature 0** (모든 경로).
2. **사고(incident) 경로 근거 = 고정 조각**: `eval/sop_eval_set.json` 의 `pinned_chunks` 를 `safety_manual_v2` 에서 chunk_id 로 지정 순서대로 조회(용어 빈도 정렬 미사용). event 를 못 정한 incident 는 기존 I 와 같이 응급처치 카테고리 검색(v2).
3. **사고 경로 프롬프트 v3**: 안전 규칙 블록을 프롬프트에서 **뺀다**. 지시는 "발췌에 있는 조치 중 지금 질문에 맞는 것 최대 3개, 각 한 줄, 서론 없이". 답 뒤에 코드가 고정 문장 1줄을 붙인다: `※ 화면의 즉시조치와 현장 책임자 지시가 이 답변보다 우선합니다.`
4. **보안(security) 경로 신설 — LLM 미호출 고정 답변**: 카메라·CCTV·영상·녹화·사진·촬영·얼굴·외부 전송·클라우드·인터넷 질문. 고정 문구는 **코드로 확인한 사실만** 쓴다 — 착수 전 확인: (a) 카메라·영상 입력 코드 없음 (b) 젯슨→노트북 전송 내용(좌표점 `points` 포함 여부 — radar_core.py 1430) (c) 노트북에서 외부(인터넷)로 나가는 호출 유무(Ollama·PostgreSQL·젯슨 UDP 외). 확인 결과를 보고에 표로 싣고, 확인 못 한 항목은 문구에 넣지 않는다.
5. 라우터 판정 순서: control → security → incident → system → other. 미공개 12문항 재확인(≥10, 사전 수정 금지).

## 3. 평가 문항 추가 (`eval/` 안)
- `eval/chip_questions.json` (신규): 경보 확인 후 띄울 추천 질문 초안 — 낙상 "환자를 옮겨야 하면 어떻게 해?", "의식이 없으면 어떻게 해?" / 협착 "끼인 사람을 어떻게 빼야 해?", "피가 많이 나면?" / 감전 "감전자를 어떻게 떼어내?", "호흡이 없으면?" / 무동작 "불러도 대답이 없으면?". 각 문항에 alert(해당 경보) 를 붙여 live 조건으로 묻는다. 채점은 `must_not_include`(sop_eval_set.json 의 해당 경보 금지어) + `fact_errors` 만, 답 전문을 보고에 싣는다(사람이 시연용 확정).
- `eval/fact_error_terms.json` 에 보안 사실 오류 표현 추가: `영상을 분석`, `영상 분석`, `녹화`, `촬영`, `카메라로` (보안 경로가 고정 답변이면 0 이어야 정상).
