## 1. 문제 (T-CC06d 조건 B 실측)
`console_ui.py` 가 시작하자마자 `SopEngineV2.prewarm()`(3736·4046줄)으로 `PREPARE_MODEL = qwen2.5:3b`(3369줄)를 올려 6종 SOP 를 만든다(`keep_alive 30m`, 2.1 GB). 경보가 없어도 적재되고, 챗봇 모델과 서로 밀어내 첫 질문 적재 25~30초, gemma2 생성 중 가용 287 MB 의 원인이 됐다. 또 캐시가 없을 때 경보 시점에 `_work_body` 가 `core.LLM_MODEL` 로 실시간 생성한다(3446~3458줄). 두 경로 모두 10/06 결정(경보 화면 생성형 AI 제외)과 어긋난다.

## 2. 할 것 — 범위는 이것뿐
1. `console_ui.py` 에 상수 `ALARM_SCREEN_LLM = False` 를 두고(주석: 10/06 결정·T-CC04~05b 근거·10/08 실측), 이것이 False 면
   - `prewarm()` 을 부르지 않는다(시작 시·PH_LIVE 전환 시 두 곳).
   - `_work_body` 는 캐시·생성 없이 **공식 매뉴얼 원문(srcs) + 실측 브리핑(brief)** 만 표시하고 끝낸다. `---AI_SOP---` 구분자가 화면 데이터에 들어가지 않는다.
   - 대시보드 AI 상태 표시는 "준비 중/6종 준비 완료" 대신 사실대로(예: "경보 화면 · 즉시조치·공식 원문, 생성형 AI 미사용"). 문구는 Claude Code 가 정하고 보고에 적는다.
2. `PREPARE_MODEL`·`prewarm`·`_gen_facts` 코드는 **지우지 않는다**(되돌리기 쉽게). `radar_core.py` 의 `USE_LLM_SUMMARY`·v1 코드는 건드리지 않는다.
3. 챗봇(`AssistantDrawer`)·모델 상수·변형 기본값은 바꾸지 않는다. EXAONE 적용은 T-CC07.
4. **[10/08 16:52 사용자 결정] 챗봇 워밍업으로 대체**: 앱 시작 시(기존 prewarm 을 부르던 자리) 백그라운드 스레드가 **챗봇이 쓰는 모델**(`core.LLM_MODEL` — 지금 gemma2, T-CC07 에서 EXAONE 으로 바뀌면 자동으로 따라감)에 짧은 요청 1회(`num_predict` 1~5)를 보내 모델을 올려 둔다. SOP·답 생성이 아니다.
   - `keep_alive` 는 워밍업과 챗봇 요청이 같은 값을 쓴다. 시연 중 내려가지 않도록 `-1`(앱이 떠 있는 동안 유지)로 하고, **앱 종료 시 `keep_alive: 0` 요청으로 내린다**(메모리 반환). 기존 챗봇 요청의 `'30m'` 도 같은 상수로 바꾼다 — 이 한 줄은 범위 안으로 본다.
   - 대시보드 AI 상태: "SOP 준비 중 n/6" 자리를 **"챗봇 워밍업 중" → "챗봇 준비 완료"(실패 시 "챗봇 준비 실패 — Ollama 확인")** 로. 경보 화면 쪽 표시는 1번 문구.
   - 워밍업 중 질문이 오면 기존 잠금(`AI_WORK_LOCK`)으로 순서대로 처리(별도 거절 문구 없음).
   - ⚠ 챗봇 요청 `timeout=30`(3197줄 부근) 은 조건 B 첫 질문 26~30초에 걸릴 수 있었다 — 워밍업 후에도 첫 질문이 20초를 넘으면 보고(타임아웃 값은 바꾸지 않는다).

## 3. 확인 (실측, 실행한 것만 완료로)
1. 변경 전후 각각: Docker + `console_ui.py --live 127.0.0.1` + `replay_jsonl.py --seq normal` 3분 → `ollama ps` 결과와 60초 시점·3분 시점 가용 메모리. **변경 후 `ollama ps` 에 모델 0개**여야 한다.
2. 변경 후 경보가 나는 재생(기본 seq)으로 낙상·감전·협착 경보 각 1회 → 경보마다 `ollama ps` 에 **생성 모델 0개**(공식 원문 검색 때문에 임베딩 모델 `bge-m3` 이 올라오면 그 사실과 크기를 기록 — 생성 모델이 아니므로 실패 아님), 경보 화면에 즉시조치·공식 원문·실측 브리핑이 뜨는지(화면 캡처 또는 위젯 텍스트 덤프로 증거).
3. 워밍업: 앱 시작 → "챗봇 준비 완료" 까지 걸린 시간, 그 직후 `ollama ps`(챗봇 모델 1개만), **첫 질문**("작업자가 넘어졌어")의 응답 시간과 둘째 질문 응답 시간. 첫 질문이 둘째보다 5초 이상 느리면 워밍업이 효과 없는 것으로 보고 원인 기록. 앱 종료 후 `ollama ps` 모델 0개.
4. ui-verify 4종(`테스트_v1결함_재발검사.py` 3회 포함), `test_chat_prompt_same.py`, `test_sop_collection_filter.py`, pyflakes, 동결 해시 시작==종료. 테스트가 SOP 캐시·AI_SOP 표시를 기대해서 실패하면 **테스트를 고치지 말고** 멈춰 보고.
