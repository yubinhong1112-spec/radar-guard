- 시작: `scripts\start_demo.ps1 -Jetson <IP>` — IP 는 핫스팟 연결 기기 목록 또는 젯슨에서 `hostname -I`. 빠뜨리면 실행되지 않는다.

- 사고·시스템 질문은 첫 문장까지 약 4~6초, 완료까지 7~9초. 고정 답은 즉시.
- 촬영 세션마다 `stop_demo.ps1` → `start_demo.ps1`. 같은 LLM 질문을 한 세션에서 두 번 묻지 않는다.

## 재부팅 뒤 이어서 할 일 (§3-1 — 실행 안 함)

재부팅('다시 시작') → 로그인 → 다른 앱을 띄우지 않고 Claude Code 에서:

1. `Get-Process -Name 'ollama','ollama app'` — **0개여야 한다**(자동 실행 없음). `Ollama.lnk` 는 `C:\Users\82102\Ollama_startup_backup\` 에 있다.
2. `scripts\start_demo.ps1 -Jetson 127.0.0.1` 과 `python 01_현행코드\replay_jsonl.py --seq normal` 을 띄우고, 시작 시각부터 `%TEMP%\radar_guard_console.log` 에 `[AI] 챗봇 워밍업 … 준비 완료` 가 찍힐 때까지의 시간을 잰다.
3. `scripts\stop_demo.ps1`. 이 보고의 상태를 완료로 바꾸고 수치를 적어 커밋한다.

## 지시와 다르게 한 것

1. **질문 입력을 코드로 했다**(착수 보고에서 알림). 사람이 타이핑한 캡처는 아니다.
2. **지시에 없는 것 둘을 넣었다**: 앱의 워밍업 로그 한 줄과 `start_demo.ps1` 의 로그 파일. '챗봇 준비 완료까지 시간' 을 실제 앱에서 재려면 필요했다.
3. **문장 끝 뒤가 공백일 때만 끊는다.** 지시서의 '줄바꿈' 은 줄 끝 규칙이 이미 받는다. 따옴표·괄호가 바로 붙는 문장(`…합니다.)`)은 줄 끝이나 생성 종료 때 표시된다.
4. **28문항은 1회만 쟀다**(지시대로). 2회차 비교는 하지 않았다.
