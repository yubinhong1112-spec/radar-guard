## 지시와 다르게 한 것

1. **메모리 하한을 1500 → 1200 MB 로 낮췄다.** 사용자가 "다 닫아도 됨" 이라고 해 배경 앱을 전부 닫았는데도(webview 12개 242 MB·SearchHost 72 MB·Widget·OneDrive·KakaoTalk 등) 가용이 1300 MB 대에서 더 내려가지 않았다. Windows 가 셸 구성요소(SearchHost·RuntimeBroker·StartMenuExperienceHost)를 다시 띄우고, 필수 상주분만 약 2.4 GB(svchost 795 · 내 세션 406 · vmmemWSL 334 · Docker Desktop 205 · com.docker.backend 158 · explorer 216 · vmmem 143)다. 지시서가 "이번 산출물은 문장 품질만 쓰고 지연은 쓰지 않는다" 고 명시했으므로 결과 타당성에는 영향이 없다고 판단했고, 결과 파일 머리말과 이 보고에 박아 넣었다. `Memory Compression` 은 207~292 MB 로 10/05 의 650 MB 보다는 나아졌다. 조건별 실제 측정 시작 가용은 1507 MB(qwen)·2747 MB(gemma2)였다.
2. **프롬프트 문구는 제가 썼다.** 지시서가 "그대로 쓰지 않아도 되나 아래 제약은 모두 지킨다" 고 했으므로 제약 7개(즉시조치 반복 금지 · 발췌에 있고 즉시조치에 없는 현장 조치만 · 최대 2개 · 정의·설명·통계·예방 설계 제외 · 40자 이내 · 없는 수치·절차 금지 · 항목마다 chunk_id 1개 · 없으면 빈 목록)를 전부 넣어 조립했다. 원문은 결과 `.md` 의 '프롬프트 원문' 절과 `.jsonl` 의 `prompt` 필드에 그대로 있다.

## 판단 요청

1. **이 방식을 계속할지 결정해야 한다.** 두 모델 모두 쓸 수 있는 보충을 만들지 못했고, 사람이 찾은 기대목록 15개를 하나도 재현하지 못했다. A) **기대목록에서 사람이 직접 골라 파일로 고정하고 AI 생성을 쓰지 않는다** B) 프롬프트를 고쳐 다시 시도한다(예: 발췌를 조각 1개씩 쪼개 묻고, 즉시조치와 겹치면 버리라고 예시로 보여준다) C) 더 큰 모델을 쓴다. — **권장 A**. 경보 화면은 심사 최우선이고(계획 §0) 보충은 1~2줄뿐이다. 사람이 15개 후보를 이미 원문 근거와 함께 찾아 놨으므로, 거기서 고르면 품질이 확실하고 10/14 동결에 맞출 수 있다. AI 생성은 승인된 문장을 **검증하는 쪽**(근거 일치·중복 검사)으로 쓰는 것이 이번 결과에 맞는 역할로 보인다.
2. **검사 3 의 중복 판정을 보강할까.** 지금은 짧은 생성 문장이 긴 즉시조치의 일부를 베껼 때 놓친다(협착 1번, 자카드 0.138). A) 포함률(생성 문장의 2-gram 중 즉시조치에 있는 비율)을 함께 보고 0.7 이상이면 중복으로 본다 B) 그대로 둔다. — **권장 A**. A 를 쓰면 협착 1번이 잡힌다(계산해 보면 0.9 이상이다, 추정 — 아직 구현·측정 안 했다).
3. **지정 조각에 상황과 무관한 절이 붙어 있는 문제.** 무동작의 `H-187-2021-0013` 에 4.5 화상 절이 붙어 있어 모델이 "찬물로 화상 부위를 적시" 를 끌어왔다. T-CC05 판단 요청 1(지정 조각 교체)과 같은 뿌리다. A) 조각을 더 좁게 다시 지정한다 B) 조각 안에서 쓸 절 범위까지 지정한다. — **권장 B**, 1번에서 A 를 고르면 자연히 해결된다(사람이 문장을 고르므로).
4. **`num_ctx` 3072 가 필요했는지.** 프롬프트가 1333~1519자였다. 제품 기본값 1536 토큰으로도 들어갈 가능성이 있지만 한국어는 글자당 토큰이 1 을 넘어 확실하지 않다. T-CC07 제품 반영 때 `num_ctx` 를 올려야 하는지는 **미확인**이다 — 1536 으로 한 번 돌려 비교하면 확정된다(이번 지시서에 없어 하지 않았다).

## 발견한 문제 (이번 범위 밖 — 고치지 않았다)

1. **`gemma2:2b` 가 `format` 스키마 + 추출 과제에서 즉시 빈 답을 낸다.** T-CC05 에서는 JSON 이 잘려 깨졌고(`num_predict 160`), 이번에는 `num_predict 400` 으로 올렸더니 깨지지 않는 대신 빈 목록을 냈다. 2B 가 스키마 출력 자체는 하지만 지시 이행을 못 한다는 뜻이다(추정).
2. **`stationary_anomaly` 의 `INSTANT_ACTION` 첫 줄이 조치가 아니다** — "사고 상황은 해소됐지만 작업자의 움직임이 확인되지 않습니다" 는 상황 설명이다. 중복 검사에서 이 줄이 비교 대상에 들어가고, T-CC05 에서 금지어 `경보 발생` 이 걸린 것과도 관련이 있어 보인다.
3. **`README.md` 미커밋 변경 138줄**이 T-CC03 때부터 남아 있다. 지시서에 없어 커밋하지 않았다.
