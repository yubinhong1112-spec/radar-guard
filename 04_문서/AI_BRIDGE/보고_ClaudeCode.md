## 한눈에

1. **문제**: 관제 화면이 뜨자마자 `qwen2.5:3b`(2.1 GB)를 올려 6종 SOP 를 만들었다. 경보가 없어도 적재되고 앱을 닫아도 30분 남았다.
2. **해결**: `ALARM_SCREEN_LLM = False` 로 사전 생성과 경보 시 생성을 모두 끄고, 그 자리에서 챗봇 모델을 1회 워밍업한다. 창을 닫으면 모델을 내린다.
3. **실측**: 변경 후 qwen2.5 적재 0회. 경보 3종 모두 생성 모델 0개. 워밍업 16.4초, 첫 질문 6.2초 · 둘째 6.7초. 앱 종료 후 모델 0개.
4. **테스트 1개를 사용자 승인으로 고쳤다** — `test_chat_prompt_same.py` 가 `keep_alive` 를 바이트 비교에서 빼고 상수와 같은지 따로 검사한다.
5. **재발검사 17a·17c 간헐 실패는 오늘 가용 1.8 GB 이상에서 재현되지 않았다** — 수정 전 20회 · 수정 후 20회 모두 통과.

## 지시와 다르게 한 것

1. **§3-1 "변경 후 `ollama ps` 모델 0개" 는 나오지 않는다.** 16:52 에 추가된 워밍업(§2-4) 때문에 챗봇 모델 1개가 올라오는 것이 의도된 동작이다. qwen2.5 는 0개다.
2. **테스트를 1개 고쳤다(사용자 승인).** `test_chat_prompt_same.py` 는 요청 본문 전체를 기준 파일과 바이트 비교해서, `keep_alive` 를 `'30m'` → `-1` 로 바꾸자 10건 전부 NG 였다(프롬프트는 같았다). 멈춰 보고한 뒤 승인받아 `keep_alive` 키 하나만 비교에서 빼고 `ui.CHAT_KEEP_ALIVE` 와 같은지 따로 검사한다. 기준 파일은 다시 만들지 않았다.
3. **감전 확정·협착 경보는 주입했다**(실측 2). 재생 데이터에 두 라벨이 없다.
4. **측정 전 앱 정리.** 1차(00시대)는 내리지 않고 그대로 쟀다. 2차(20시대) 재발검사 40회 전에 사용자 지시로 Claude 데스크톱·Codex 앱·`cowork-svc` 를 내렸다(가용 911 → 2327 MB). Chrome 은 켜 둔 채였다.

## 판단 요청

1. **`keep_alive: -1` 은 앱이 비정상 종료되면 모델이 남는다.** 작업 관리자 종료·강제 종료·충돌 시에는 `keep_alive: 0` 요청이 나가지 않는다. `ollama stop gemma2:2b` 로 내려야 한다. 시연 체크리스트에 넣을지 결정 필요.
2. **외부에서 창 닫기 신호를 보내면 프로세스가 8초 안에 끝나지 않았다**(변경 전·후 같음). 모델 내리기는 그 경우에도 동작했다. 원인은 보지 않았다.
3. **경보 패널의 고정 제목이 아직 `공식 안전 매뉴얼 · 실측 브리핑 · AI 보조 요약` 이다**(`SopView`). AI 요약은 이제 뜨지 않는다. 범위 밖이라 고치지 않았다.
4. **재발검사 17a·17c.** 메모리가 낮을 때만 나오는 것으로 보이지만(추정) 원인은 여전히 미확인이다. 복합 경보 표시는 시연 화면이다.
5. **`chat_eval.py` 의 `keep_alive '30m'`** 은 측정 도구라 그대로 뒀다. 앱과 값이 달라졌다.
6. **워밍업이 실패해도 다시 시도하지 않는다.** Ollama 가 늦게 뜨면 카드가 "준비 실패" 로 남고, 첫 질문이 모델을 올린다(그 질문은 느리다).
