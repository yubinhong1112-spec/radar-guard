## 지시와 다르게 한 것

1. **조건 B 를 재지 않았다.** 사용자는 전원을 종료한 뒤 수동으로 다시 켰다고 했다. 그런데 Windows 가 기록한 LastBootUpTime 은 10/06 19:23:58 로 바뀌지 않았다 — 이 노트북은 '빠른 시작' 이 켜져 있어(`powercfg /a` 로 확인) 종료 후 켜기가 부팅으로 잡히지 않는 것으로 보인다(추정). 지시서는 재부팅하지 않았으면 조건 B 를 무효로 적으라고 했고, 사용자가 "그러면 조건 B 는 빼고 진행하라" 고 지시했다.
2. **측정 전에 사용자 지시로 앱을 내렸다** — Claude 데스크톱·Codex 앱·Edge·Teams·Samsung Notes 트레이. Docker·WSL·알약·Free Download Manager 는 남겼다.
3. **검색 호스트를 다 내리지 못했다.** `SearchFilterHost`·`SearchProtocolHost` 는 접근 거부로 종료되지 않아 `SearchHost` 만 내렸다.
4. **첫 측정 시도 1회가 측정 전에 실패했다.** 실행 스크립트의 한글 경로가 깨져 `chat_eval.py` 를 열지 못했다(기록 없음, 잃은 회차 없음). 스크립트를 고쳐 다시 돌렸다.
5. **`chat_eval.py` 의 `--route-dump` 는 DB·임베딩 모델 접속 검사를 거친다.** 생성 LLM 은 부르지 않았지만 "LLM 없이" 를 순수 함수만으로 하지는 않았다 — 측정과 같은 코드로 경로를 찍으려고 그렇게 했다.
6. T-CC06c 보고에 '다음에 필요한 것' 절이 없어, 메모리 확보 절차는 그 보고 '지시와 다르게 한 것' 2번(모델 내림 → 검색 호스트 종료 → 25초 대기)을 따랐다.

## 판단 요청

1. **조건 B 가 필요해지면 다시 재야 한다.** 블라인드 채점에서 치명 실패 수 차이가 0~1건이면 판정 규칙 2·3번에 쓸 값이 없다. 그때는 시작 메뉴의 **'다시 시작'** 으로 재부팅한 직후 조건 B 만 재면 된다(두 모델 1회씩). 종료 후 켜기는 부팅으로 잡히지 않는다.
2. **K3 의 20자 일치 규칙을 그대로 치명 실패로 볼지.** 두 모델이 같은 두 문항(P-01·P-02)에서 걸려 모델 선택은 바뀌지 않는다. 다만 P-02 는 `system` 경로라 프롬프트에 시스템 명세가 들어가 있고, 그 문장을 옮기는 것이 유출인지 정상 설명인지는 답 전문으로 봐야 한다.
3. **F-07·S-03 의 `incident` 오분류.** '낙상'·'움직이지 않는' 낱말 때문에 시스템 질문이 사고 대응 경로로 간다. 두 모델이 같은 프롬프트를 받으므로 비교는 공정하지만, 이 두 문항의 답 품질은 모델이 아니라 라우터의 문제일 수 있다. 채점에서 따로 볼지, T-CC07 에서 라우터를 고칠지 결정 필요.
4. **gemma2 가 EXAONE 보다 메모리 여유가 적게 나온 것**(최저 222 · 8 MB vs 994 · 921 MB)은 시작 조건이 달라 모델 차이라고 말할 수 없다. 조건 B 를 재게 되면 두 모델의 시작 가용을 맞춰야 한다.
5. **답 잘림이 많다**(gemma2 8/28 · EXAONE 6/28, num_predict 100). 사고 대응 문항에서 gemma2 는 8문항 중 5문항이 잘렸다. 시연에서 문장이 중간에 끊겨 보이는지 확인이 필요하다.
