- **`electric_shock_risk` 1위가 「니엘센법·주상 인공호흡법」(전주 승주 구조)이다.** 정작 「7. 감전사고시의 응급조치」는 점수 3으로 **17개 중 12위**다. `환자`·`호흡` 이 많이 나오는 구조 절차 쪽이 용어 빈도 정렬에서 이긴다. 위 3번의 "1번 작업자" 문장이 여기서 왔다.
- **`leakage_current` 가 v1 에서는 누설전류가 아니라 과전류 절을 1위로 뽑고, v2 에서는 누설전류 절을 제대로 뽑는다.** v2 채택 근거가 될 숫자다.
- **`pinching` 의 응급처치 카테고리 1위 점수가 v1 2점 · v2 1점이다.** 사실상 아무 청크도 맞지 않는다는 뜻이다(끼임 용어가 응급처치 문서에 거의 없다).
- 덤프의 선택 결과와 `search_sop_documents` 실제 결과를 매번 대조했고 **불일치 0건**이다(v1·v2 둘 다). 선택 규칙을 잘못 옮기지 않았다는 확인이다.

**새로 발견한 문제 — 동점일 때 선택이 비결정적이다.** `electric_shock_risk` 의 1위와 2위가 **둘 다 점수 13**인데, 선택 SQL 에 `ORDER BY` 가 없고 파이썬 `sort` 는 안정 정렬이다. 즉 어느 청크가 뽑히는지가 **DB 행 반환 순서에 좌우된다**. 같은 입력에 다른 조각이 나올 수 있다. 판단 요청 1번.

1. **`--facts sample` 의 실측값을 3종만 넣었다.** `PREPARE_EVENTS` 6종 중 `overcurrent`·`leakage_current`·`stationary_anomaly` 는 `chat_eval_set.json` 의 alert 에도, `events_ui_animation_confirmed_0824.jsonl`(3줄: fall·pinch·shock)에도 없다. 지시서가 정한 두 출처를 벗어나 값을 지어내지 않고 `facts` 를 비우고 돌렸으며, 그 사실을 `facts_source` 에 적었다. 착수 보고에서 미리 올린 내용이다.
2. **첫 실행 2건을 폐기하고 기록을 고쳐 다시 돌렸다.** `_gen_facts` 는 `fact_block` 이 비면 `core.LLM_MODEL` 이 아니라 `PREPARE_MODEL` 을 쓴다(console_ui.py 3011). 그래서 위 3종은 `--facts sample --model gemma2:2b` 로 불러도 실제로는 qwen 으로 돌았는데 첫 기록이 `model: gemma2:2b` 로 적고 있었다. 실제 사용 모델을 따로 적고 요청과 다르면 `⚠` 를 붙이도록 고친 뒤 두 조건을 다시 측정했다. 제품 동작은 바꾸지 않았다 — 기록만 고쳤다.
3. **`capture()` 가 응답 본문을 먼저 다 읽는다.** 스트리밍 경로의 `load_duration`·`eval_count` 를 얻으려면 응답 원문이 필요하고 제품 코드를 못 고치므로, `urlopen` 대역이 본문을 읽어 두고 `_gen_facts` 에 넘긴다. `on_update` 를 쓰지 않으므로 생성 결과는 같지만, 화면 점진 표시의 **체감 지연은 이 측정으로 알 수 없다**.

## 판단 요청 (사용자·Cowork 가 정할 것)

1. **동점 청크 선택의 비결정성을 어떻게 막을까.** `electric_shock_risk` 1·2위가 둘 다 점수 13이고 선택 SQL 에 `ORDER BY` 가 없다. A) 계획 2단계의 '이벤트별 지정 chunk_id 고정' 으로 한번에 해결한다 B) 그 전에 임시로 정렬 키를 추가한다(점수 → `chunk_id`/`page` 오름차순). — **권장 A**. 어차피 2단계에서 지정으로 바꿀 것이고, B 는 제품 코드를 또 한 번 건드린다. 다만 그때까지 시연에서 조각이 바뀔 수 있다는 것은 알고 있어야 한다.
2. **경보 SOP 정답 기준(`sop_eval_set.json`)에 넣을 항목을 어디서 뽑을까.** 지금 조각 선택이 틀린 절을 주고 있어(위 4번), 생성문이 "맞게" 쓴 것인지 "틀린 근거를 잘 요약한" 것인지 구분되지 않는다. A) 기준을 **매뉴얼 원문**에서 뽑고 조각 선택과 무관하게 채점한다 B) 현재 조각 기준으로 채점한다. — **권장 A**. 그러면 조각 선택 문제가 점수로 드러난다.
3. **스트리밍 경로(gemma2 + facts)의 형식 깨짐을 어떻게 다룰까.** 실측값이 있는 3종이 10줄·6줄·9줄로 나오고 `##`·`**`·`-` 가 섞인다. A) 계획 2단계의 '짧은 답 프롬프트' 에서 같이 고친다 B) 코드 후처리로 4줄만 추려 표시한다 C) 사전 생성 성공률을 100% 로 올려 이 경로를 안 타게 한다. — **권장 A 와 C 를 같이**. 지금 qwen 사전 생성은 6/6 통과이므로 C 는 거의 달성돼 있고, 남는 위험은 앱 시작 때 prewarm 이 실패하는 경우다.
4. **`테스트_v1결함_재발검사.py` 가 실패해도 종료코드 0 인 것을 고칠까.** 이번에 58/2 가 한 번 나왔고 종료코드는 0 이었다. 출력을 읽지 않으면 놓친다. A) `sys.exit(1 if NG else 0)` 을 넣는다 B) 그대로 두고 ui-verify 절차에서 출력을 읽는다. — **권장 A**. 다만 제품 코드가 아니라 테스트 스크립트이고, 이번 작업의 '제품 코드 무변경' 범위 밖이라 손대지 않았다.
5. **pinching 의 응급처치 조각이 사실상 매칭되지 않는다**(v1 2점 · v2 1점). A) `SOP_RESPONSE_TERMS['pinching']` 에 절단·출혈·지혈 용어를 넣는다 B) 2단계의 chunk_id 고정에서 H-187 4.3 절단부 처치를 직접 지정한다. — **권장 B**. A 는 또 용어 빈도에 의존한다.
