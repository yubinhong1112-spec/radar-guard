## A. T-CC07b3 판단 요청 처리 (Cowork 결정)
1. **R01 미탐 "구조 어떻게 해?"**: 협착 경보·협착 라우팅일 때 단독 `구조` 도 잡되, 질문에 `SYSTEM_NOUNS`(레이더·시스템·젯슨 등)가 있으면 제외. 확인: "구조 어떻게 해?"(협착) → R01, "시스템 구조가 어떻게 돼?"(협착 경보 중) → R01 아님.
2. **F-01 보안 등급 지어내기(10/10회 "높음")**: 고정 답 T02 — (`등급`·`보안 등급`·`출입 등급`·`권한 등급`·`보안등급`) 질문 → "Radar-Guard 에는 구역 출입·보안 등급 정보가 없습니다. 보안 담당자에게 확인하십시오." 오탐 확인 3문장(예: "경보 등급이 뭐야?" 는 기존 경로 유지 — 경보 등급 설명은 시스템 질문).
3. **워밍업 방식 B 적용**: 1토큰 워밍업 뒤 실제 J3 프롬프트 1개(EA-01)를 `num_predict` 100 으로 돌리고 버림. 근거: 첫 질문 8.9 → 6.1~6.3초, 시작 시간 +8.6초는 심사 전이라 무관. 카드 문구는 그대로(완료 시점만 늦어짐).

6. **경보 중 시스템 질문이 사고 경로로 바뀌는 문제 (10/10 Cowork 확인, 외부 검토 의견 반영)**

   - 해결: 경보 연동 덮어쓰기는 route 가 `incident`·`other` 일 때만(칩 7문항 경로 유지). `system` 은 그대로 시스템 경로(실측 블록은 지금처럼 붙여도 됨).
   - 확인: 경보 3종(낙상·협착·감전 확정) × 시스템 질문 5개(RTC·경과시간, 레이더 원리, 정지한 사람 추적, 노트북 꺼지면 차단, 개인정보) → route `system`. 칩 7문항 → 기존과 같은 incident·같은 근거. 61·28문항 route 덤프 전후 비교(바뀐 문항 ID 목록).
   - 보고 시 **고정 답 성공률과 생성 답 품질(질문 해결·근거 밖 내용·잘림)을 따로** 적는다.
