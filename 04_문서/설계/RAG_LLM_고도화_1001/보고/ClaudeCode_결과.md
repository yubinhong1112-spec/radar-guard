2. **event_action 지시 예시 문항 일부를 바꿨다.** "절단된 부위 보관" 은 검색되는 청크(H-187 11쪽 = 전기화상·뇌진탕, B-M-37 43쪽 = 비상정지장치)에 없어 정답 문구를 쓸 수 없었다. 대신 청크 원문에 있는 내용으로 EA-03/EA-06(비상정지·재가동 잠금)을 넣어 낙상 2·감전 2·협착 2 로 맞췄다.
3. **live_status 의 `ds_last` 에 같은 줄의 `ds_max` 값을 넣었다.** 젯슨이 보내는 `ds_last` 가 jsonl 에 없다. 같은 줄 evidence 의 실측 `ds_max=1.148` 을 쓰고 `basis` 에 그 사실을 적었다. → **판단 요청 4번**

## 발견한 문제 (이번 범위 밖)

- **청크 원문의 공백이 사라져 있다.** 검색된 H-187·B-M-37 청크가 `환자를움직이지말고손으로머리를고정한다` 처럼 공백 없이 색인돼 있다(24.29% 보고와 일치). 그래서 평가셋 `must_include` 를 공백을 넘지 않는 짧은 조각으로만 쓸 수 있었다. Codex 의 v2 재적재가 이것을 고치는 작업이다.
- **fall_detected 검색 결과에 `119` 가 없다.** H-187 에서 선택되는 청크 2개(3쪽 골절, 11쪽 전기화상·뇌진탕)에 119 신고가 들어 있지 않다. 낙상 응급처치에서 119 가 빠진 근거만 LLM 에게 주고 있다. `SOP_RESPONSE_TERMS['fall_detected']` 에 `119` 가 있는데도 그 용어가 많은 청크가 선택되지 않는다.
- **pinching 의 응급처치 청크가 주제에서 벗어나 있다.** `00_응급처치_공통` 에서 뽑히는 청크가 전기화상·뇌진탕 11쪽이다. 끼임 사고의 실제 상해(절단·출혈)에 대한 내용이 아니다.
- **검색 context 가 1400자 한도를 한참 밑돈다.** fall 842자 / electric 1108자 / pinching 660자. 문서당 청크 1~2개만 가져오는 현재 설정에서는 `[:1400]` 절단이 거의 작동하지 않는다.
